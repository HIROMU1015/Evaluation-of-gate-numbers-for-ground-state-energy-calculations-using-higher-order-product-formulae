# GPU側Codexへの依頼：m=3候補のH7直接検証

4次PFの「コストの低さ」と「有限時間でも $e_{\mathrm{direct}}(t)\simeq\alpha t^4$ を保つこと」を両立できるか調べている。H2/H4/H5だけで選んだ次の3候補はH6の未使用サイズ検証に合格したが、ローカルCPUではH7のPFユニタリ構築に時間がかかったため中断した。

GPUでは係数探索をやり直さず、この3候補のH7直接検証だけを完了してほしい。

| 役割 | 候補名 | 係数 $w_0,w_1,w_2,w_3$ |
|---|---|---|
| コスト優先 | `m3_local_c1_r2_s007` | $-0.4737318199452465,\ 0.3316118001935053,\ 0.20922466907827963,\ 0.19602944070083841$ |
| 中間 | `m3_local_c3_r2_s000` | $-0.4886775900905438,\ 0.35020453881642843,\ 0.20593217562661245,\ 0.18820208060223098$ |
| 予測精度優先 | `m3_local_c2_r0_s000` | $-0.5217979095146608,\ 0.3857554919429845,\ 0.20720451613362992,\ 0.16793894668071602$ |

各候補は、上表の係数から既存コードと同じ回文対称な2次公式の合成列を作る。探索時に用いたH6のCPU結果は

`artifacts/pf_cost_predictability_m3_holdout/H6_H7_holdout.json`

に保存してある。H7の途中レコードは中断記録であり、結果として使用しないこと。

## 実行方針

1. まずH6のコスト優先候補について $t=t_{\mathrm{ana}}$ の1点だけをGPUで再計算し、CPU基準と一致することを確認する。
2. 一致したらH7で3候補を計算する。短時間フィットから各候補の $\alpha$ と $t_{\mathrm{ana}}$ を求め、

   $$
   t/t_{\mathrm{ana}}=0.1,\ 0.3,\ 0.5,\ 0.7,\ 0.9,\ 1.0,\ 1.1,\ 1.2,\ 1.4
   $$

   の固定格子で $e_{\mathrm{direct}}(t)$ とコストを求める。
3. GPUサーバーで整備済みの直接対角化コードを使ってよい。今回ローカルで重かったのは固有値分解よりPFユニタリ構築なので、GPUでの密行列構築を優先する。最終分解をCPUへ戻して行っても、GPU上で行ってもよい。
4. 厳密基底状態との重なりと、隣接時刻の固有ベクトルとの連続性から、同じPF固有枝を追跡する。
5. H7では、各点の符号付き固有値シフト、$e_{\mathrm{direct}}/e_{\mathrm{model}}$、直接コスト、基底状態重なり、隣接時刻重なり、固有対残差を保存する。10%則の最後の合格点、最初の不合格点、格子上の最小コスト時刻も集計する。

H6のCPU基準との確認では、少なくとも符号付き固有値シフトの絶対差 $10^{-10}$ Hartree以下、コスト相対差 $10^{-6}$ 以下を目安とする。枝選択が異なる、またはこの精度を満たさない場合はH7へ進まず、原因を報告する。

## 全体の研究方針

最終目的は、QPEコストが低いだけでなく、解析に用いる短時間則がコスト最適時刻の近くまで保たれ、解析値から実コストを予測しやすいPFを作ることである。したがって、候補の評価では次の2軸を分けずに記録する。

- 実際の直接コストと、その最小値。
- $e_{\mathrm{direct}}(t)/(\alpha t^4)$、解析コストの予測誤差、有効次数などで測る予測しやすさ。

最小の $\alpha$ だけ、または一つの時刻での偶然の誤差相殺だけで候補を選ばない。係数探索に使用した系と未使用サイズ検証に使う系を明確に分け、未使用系の結果を見た後で同じ候補の係数や合否基準を調整しない。

係数探索はまず計算の軽い $m=2,3$ を中心とし、$m=4,5$ は追加段によるコスト増を上回る改善が見込める場合に広げる。現時点ではm=3候補が初期の有力候補であるが、H7の結果が出るまでは確定しない。まずH-chainで方法を固め、H-chain以外の分子への検証は後の段階で行う。

## H7完了後の段階的な検証

以下は今後GPU側で続ける可能性がある作業の順序であり、今回のH7結果を報告する前には開始しない。

1. H7の未使用サイズ検証を確認し、残す候補を固定する。不合格の場合は、不合格理由を保存して係数探索へ戻り、H7上で係数を調整しない。
2. 候補固定後に初めて、H6/H7の格子上の最小値付近だけを細分化し、$e_{\mathrm{model}}$を使わない直接コストから真の最適時刻 $t_*$ を求める。この段階では適応的な時刻探索を用い、不要なPFユニタリ構築回数を減らす。
3. H8以降は、直接対角化が現実的な最大サイズまで1サイズずつ進める。各サイズの代表1時刻で時間とメモリを測ってから時刻探索を開始し、PFユニタリ構築の再利用、回文段の再利用、独立時刻のGPU並列化を優先する。
4. より大きい系で直接対角化が現実的でなくなった場合は、反復法や固定小次元射影の値を自動的に $e_{\mathrm{direct}}$ とみなさない。まず、直接計算できた最大系までの $t_*$ と最小コストが系サイズに対して安定に外挿できるかを、未使用サイズを残して検証する。
5. 近似固有値法を将来試す場合は、直接対角化できる系で誤差、枝選択、コストを較正し、保証できる範囲を明記する。反復回数を増やせば必ず正しい枝へ収束するとは仮定しない。

各段階では、使用commit、計算環境、係数、時刻、枝選択規則、途中終了を機械可読な形で残す。長い計算は候補・時刻ごとに再開可能にし、完了済み結果を再計算しない。次段階へ進む前に短い結果表と所要時間見積りを報告し、確認を待つ。

## 今回行わないこと

- 係数、時刻格子、合否基準の再調整。
- $t_*$ 周辺の細分化。
- H8以降の計算。
- 反復法や射影法への置換。

出力は既存JSONを上書きせず、新しい成果物ディレクトリへ保存する。計算時間はPFユニタリ構築と固有値処理を分けて記録する。今回のH7検証が完了した時点で一度停止する。コード、軽量なJSON、短い報告書を結果用ブランチへコミット・pushし、`main` へは統合しない。
