## 2. Track Rのrank continuation

主解析では、各rank自身のbranch historyを使います。

各systemについてcandidate timesを

`r=0.5 -> 0.65 -> 0.8`

の順に処理し、各rank

`m = 1, 2, 4, 8, 16, 32`

について、

- 最初の時刻ではそのrankのfrozen H-reference ruleでbranchを選択。
- 次の時刻では、同じrankの直前時刻で選択したvector/projectorをcontinuation anchorにする。

すなわち、rank mのtrajectoryはrank m自身で閉じます。

rank32 selected vectorを他rankへ流用しない。
rank8 selected vectorを全prefixへ流用しない。

primary analysis ranksは従来どおり

`m = 4, 8, 16, 32`

です。

prefix widthは事前登録どおり、

- m4: `abs(delta_M(4)-delta_M(2))`
- m8: `abs(delta_M(8)-delta_M(4))`
- m16: `abs(delta_M(16)-delta_M(8))`
- m32: `abs(delta_M(32)-delta_M(16))`

とし、

`w_M(m)=max(local_width(m), prefix_width(m))`

を使用します。

このrank-specific continuationをTrack Rの新しいmechanistic diagnosticの主結果とします。

### 旧rank8 reproduction control

既存H-chain formal rank8結果は変更しません。

旧 `analyze_coordinate` の、

「previous primary rank8 selected vectorを全prefix analysisへ渡す」

という既存規則を、同じcached UQ/HQから別controlとして再現してください。

目的は、

1. 保存済みrank8 point / branch / width / numerical gateを再現できることの確認。
2. 新rank-specific continuationによって生じる差をbranch-policy differenceとして識別すること。

です。

旧rank8 controlのwidthを新rank-specific primary widthへ置き換えない。
逆に、新rank-specific結果で旧formal rank8 resultを再採点・上書きしない。

追加PF/H actionが不要な形でcontrolを作成してください。

旧rank8 reproductionが保存結果とnumerical tolerance内で一致しない場合は、
`rank8_reproduction_control_failed_review_required`
としてTrack Rのscience interpretationを停止し、結果依存の修正を行わないでください。
